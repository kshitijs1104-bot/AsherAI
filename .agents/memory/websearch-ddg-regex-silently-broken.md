---
name: DuckDuckGo result-link regex was silently broken
description: websearch.ts's URL extraction never matched real DDG HTML, so live web search silently returned empty:true on every query, unconditionally — the actual root cause behind Vera fabricating specific real-world facts (fake school names/stats) on out-of-precedent queries.
---

`webSearch()` in `artifacts/api-server/src/lib/websearch.ts` used `/uddg="([^"]+)"/g` to pull result URLs out of DuckDuckGo's HTML search page. Real DDG markup wraps each result as `href="//duckduckgo.com/l/?uddg=<url-encoded-target>&amp;rut=<hash>"` — the target URL is a query-param *value* inside `href="..."`, not its own standalone `uddg="..."` attribute. The regex never matched anything, so `resultUrls` was always `[]` and every single web search call returned `{ sources: [], empty: true }`, regardless of query — verified live: raw DDG response had 10 real on-topic results, 0 extracted.

**Why:** Found while investigating why Vera confidently invented specific fake schools (names, "≈350 pupils", made-up neighborhoods) when asked for real Cambridge-curriculum schools in Mumbai. `ai.ts`'s `noPrecedentInstruction` explicitly told the model "if the web search came back empty, answer from your own general knowledge instead; still be direct and specific rather than vague" — combined with a search that was *always* empty, every out-of-dataset factual question got routed straight to confident fabrication, and the model had no way to know the "live search" it was told ran had actually returned nothing real.

**How to apply:** Fixed the regex to `/href="[^"]*[?&]uddg=([^&"]+)/g` + `decodeURIComponent` on the capture group (see the fix commit). Also softened the empty/no-precedent instruction in `ai.ts` to stop encouraging confident invention of specific real-world names/stats when ungrounded — added a `namedEntityGuard` block requiring specific factual claims (names, stats, addresses) to come from an actual source, while still allowing direct/concrete general strategic reasoning. If Vera's answers to out-of-dataset factual questions ever look suspiciously confident again, first re-verify `webSearch()` is actually returning real sources (log `resultUrls.length` or check `empty`) before assuming it's a pure prompting/model issue — a silent zero-results bug here is invisible from the outside since the code path still "succeeds" and returns a well-formed (empty) result.
